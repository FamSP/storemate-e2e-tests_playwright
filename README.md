# StoreMate E2E Tests (Playwright)

ชุดทดสอบอัตโนมัติของฟังก์ชันฝั่งลูกค้า ระบบ StoreMate แปลงมาจากเอกสาร **StoreMate-Test-Cases.docx**
ครบ 101 Test Case (US-01 ถึง US-20) ชื่อเทสขึ้นต้นด้วยรหัสใหม่และรหัสเดิม เช่น `TC-01-01 (TC1001) สมัครสมาชิกสำเร็จ`

## ติดตั้ง

ต้องมี Node.js 18 ขึ้นไป

```bash
npm install
npx playwright install chromium
copy .env.example .env
```

จากนั้นแก้ค่าใน `.env` (บัญชีลูกค้า, สินค้าที่ใช้ทดสอบ ฯลฯ) ห้าม commit ไฟล์ `.env`

## รันเทส

| คำสั่ง | ทำอะไร |
|---|---|
| `npm test` | รันทั้งหมด |
| `npm run test:guest` | เฉพาะเทสที่ไม่ต้องเข้าสู่ระบบ |
| `npm run test:customer` | เฉพาะเทสของบัญชีลูกค้าหลัก (เข้าสู่ระบบอัตโนมัติก่อน) |
| `npm run test:fresh` | เฉพาะเทสที่สมัครบัญชีใหม่ขึ้นมาใช้ |
| `npx playwright test -g "TC-16-01"` | รันเทสเดียวตามรหัส |
| `npm run test:headed` | รันแบบเห็นหน้าจอเบราว์เซอร์ |
| `npm run report` | เปิดรายงาน HTML หลังรันเสร็จ |

ถ้าเทสไม่ผ่าน จะมีภาพหน้าจอ วิดีโอ และ trace อยู่ใน `test-results/` (เปิด trace ด้วย `npx playwright show-trace <ไฟล์ trace.zip>`)

## ข้อควรรู้

- **เทสเขียนกับเว็บจริง** ตัวเลือก (selector) มาจาก `data-test` ในโค้ด storemate และข้อความแจ้งเตือนคัดลอกจากโค้ดตรงตัว
- **ข้อมูลจริงจะเปลี่ยน:** เทสสั่งซื้อ/ชำระเงินสร้างคำสั่งซื้อจริงและตัดสต็อกของ `PRODUCT_ID` เทส guest/fresh สมัครบัญชีใหม่ (อีเมล `@storemate-test.com`) ควรรันกับระบบทดสอบ หรือเติมสต็อกเป็นระยะ
- **สินค้าที่ใช้ต้องพร้อมขาย:** ณ 11/10/2569 สินค้า 28 และ 30 ที่เทสเดิมใช้ขึ้น "สินค้าจะมีเร็วๆนี้" (สต็อกหมด) จึงเปลี่ยนค่าเริ่มต้นเป็น 53 และ 64
- **รันทีละเทส (workers: 1)** เพราะทุกเทสใช้รถเข็น/ที่อยู่ของบัญชีเดียวกัน
- **เทสที่จะถูกข้าม (skipped) ถ้าข้อมูลไม่พร้อม:**
  - TC-02-03 ถ้าไม่ได้ตั้ง `SUSPENDED_EMAIL`
  - TC-03-02 ถ้าทุกหมวดมีสินค้า
  - TC-06-03, TC-06-04, TC-07-04 ถ้าสต็อกมากกว่า 150 ชิ้น
  - TC-08-05 ถ้าไม่ได้ตั้ง `UNAVAILABLE_PRODUCT_ID`
  - TC-17-06, 17-07, 17-08, 17-10 ถ้าบัญชีไม่มีคำสั่งซื้อสถานะ ที่ต้องได้รับ / สำเร็จ / คืนเงิน (ต้องให้เจ้าของร้านเปลี่ยนสถานะ)
- **TC-16-03 PromptPay** ทดสอบอัตโนมัติได้ถึงขั้นแสดง QR Code ส่วนการสแกนจ่ายจริงต้องทดสอบด้วยมือ
- **TC-16-09 QR หมดอายุ** ใช้ `page.clock` เร่งเวลาของหน้าเว็บ ไม่ต้องรอจริง

## สิ่งที่เทสพบว่าต่างจากเอกสาร

- **TC-06-03:** หน้ารายละเอียดสินค้าปิดปุ่ม + เมื่อจำนวนเท่าสต็อก จึงไม่มี toast "จำนวนสินค้าในสต็อกไม่เพียงพอ" ตามเอกสาร เทสจึงตรวจว่าปุ่ม + ถูกปิด
- **TC-01-13:** ข้อความในโค้ดสะกดว่า "รหัสผ่านต้องมี**ตัวตัว**พิมพ์เล็ก…" (คำซ้ำ) เทสยอมรับทั้งสองแบบ
- **TC-01-09 / TC-01-10:** backend ในโฟลเดอร์ store-mate-api ตอบข้อความภาษาอังกฤษ "Exist by email / Exist by phone" แต่เอกสารระบุภาษาไทย เทสยอมรับทั้งสองแบบ
- **TC-12-01:** โค้ดหน้าเว็บส่ง `isDefault: false` ตอนเพิ่มที่อยู่ แต่เอกสารบอกว่าที่อยู่ใหม่ต้องเป็นค่าเริ่มต้น เทสตรวจแบบ soft (รายงานแต่ไม่หยุด)
- **US-07 (TC-07-08):** ผู้ที่ยังไม่เข้าสู่ระบบไม่มีไอคอนรถเข็นบนแถบเมนู เทสจึงเปิด `/shopping-cart` ตรง
